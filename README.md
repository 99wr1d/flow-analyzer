# FlowAnalyzer

Футбольный видеоанализатор — настольное приложение (Electron + React + TypeScript).
Сейчас готовы: безопасное окно, тёмный интерфейс, импорт видео и плеер (пуск/пауза, скорость, перемотка, громкость, таймлайн), покадровый переход, рисование поверх видео (стрелки, линии, круги, текст), **разметка поля и рисунки «на траве» в перспективе** (кольца, стрелки, линии, подписи, линейка в метрах), **стартовый экран с библиотекой проектов** (карточки с эскизами, поиск, типы проектов), разметка эпизодов тегами и **оценки эпизодов** («хорошо», «плохо», «разобрать»), настройки с переназначаемыми горячими клавишами, сохранение и открытие проектов (`.flowproj`), **экспорт клипов в MP4** (отдельные файлы, одна подборка или всё видео целиком, через FFmpeg, при желании **с нанесёнными рисунками** и стоп-кадрами), **статистика** по эпизодам (таблица, диаграммы, выгрузка в CSV) и установщик для Windows.
Дальше: трекинг игроков.

## Требования

- Windows 10/11
- Node.js 24
- npm

## Команды

```bash
npm install          # установить зависимости
npm run dev          # запустить приложение в режиме разработки
npm run lint         # проверка кода
npm run typecheck    # проверка типов
npm test             # юнит-тесты (vitest)
npm run test:e2e     # сборка + тесты приложения в Electron (Playwright)
npm run build:win    # установщик: dist/FlowAnalyzer-Setup-0.13.0.exe
```

Окна автотестов открываются за пределами экрана и не забирают фокус, чтобы не мешать работе.
Чтобы увидеть окно при отладке теста, задайте `FLOW_SHOW_WINDOW=1`. Тесты работают в своих временных папках:
`FLOW_USER_DATA` (данные приложения) и `FLOW_LIBRARY_DIR` (синоним `FLOW_PROJECTS_DIR`; папка проектов по умолчанию) — настоящие `%APPDATA%\FlowAnalyzer`
и «Документы» они не трогают.

## Стартовый экран

При запуске открывается **стартовый экран** — список проектов (если при запуске не передан файл `.flowproj`: двойной щелчок
по файлу или командная строка открывают проект сразу). Вернуться к нему можно кнопкой **«Главная»** (значок домика) слева
вверху, пунктом меню «Проект» → «Главная» или `Ctrl+H` (команда «На главную», клавишу можно сменить в «Настройки» →
«Горячие клавиши»). Если в проекте есть несохранённое, приложение сначала спросит: «Сохранить», «Не сохранять», «Отмена».

- **Верхняя панель:** «Новый проект» (`Ctrl+N`), «Открыть файл…» (проект из `.flowproj`), «Просто открыть видео» (быстрый
  просмотр без проекта — безымянный проект, сохранить можно позже), шестерёнка настроек.
- **Карточки проектов.** На карточке: кадр из видео (эскиз), название, тип (Матч / Тренировка / Скаутинг / Другое), дата,
  имя видео, длительность, «N эпизодов · M рисунков», «изменён 2 ч назад». Клик — открыть проект (всё как при обычном
  открытии: если видео не нашлось, предложат «Указать видео…»). Кнопка «⋯» или правый клик — меню: «Открыть», «Показать в
  папке», «Свойства…», «Убрать из списка». «Убрать из списка» только убирает проект из списка, файлы остаются на диске. «Удалить…» (с подтверждением) переносит файл проекта в Корзину Windows, а не стирает навсегда; видеофайл не затрагивается. Проект из папки FlowAnalyzer из списка не убирается (он вернулся бы при следующем просмотре папки) — его можно только удалить.
  В меню у такого проекта об этом сказано, и предлагается «Удалить…» или «Показать в папке».
- **Фильтры:** вкладки «Все · Матчи · Тренировки · Скаутинг · Другое» с числом проектов, поиск по названию и имени видео
  (без учёта регистра, «ё» = «е»), сортировка: «Изменены» (новые выше, по умолчанию), «Название», «Дата матча».
- **Особые карточки.** Файл проекта пропал — серая карточка «Файл не найден» с кнопками «Найти…» (указать, где он теперь:
  путь в списке обновится) и «Убрать из списка». Файл повреждён или не проект — карточка «Проект не читается» с причиной.
  Пустой список — приветствие с кнопкой «Новый проект». Плашка «Найдена несохранённая работа» после сбоя показывается и здесь.
- **«Новый проект».** Окно: название (обязательно, до 80 символов), тип, дата (по умолчанию сегодня), заметки (до 500
  символов), видео («Выбрать видео…», обязательно). Файл `<название>.flowproj` создаётся в папке проектов
  (`Документы\FlowAnalyzer`; если имя занято — `<название> (2).flowproj`), проект открывается, а `Ctrl+S` дальше сохраняет без
  диалога. «Сохранить как…» работает как раньше. Если названия нет, оно подставляется из имени видео.
- **Свойства проекта.** «Проект» → «Свойства проекта…» (в открытом проекте; правка помечает проект несохранённым и пишется
  вместе с работой) и «Свойства…» в меню карточки (проект не открыт: правка пишется прямо в его файл).

Откуда берётся список: `library.json` в папке данных приложения (путь, когда добавлен и когда открыт — для каждого
проекта, который вы создавали, открывали или сохраняли; без ограничения числа) плюс файлы `.flowproj`, найденные в папке
проектов (сама папка и подпапки первого уровня). Меню «Последние проекты» (10 штук) осталось прежним. Для каждой карточки
main читает файл проекта и присылает интерфейсу только короткую сводку (название, тип, дата, имя видео, длительность,
число эпизодов и рисунков, время изменения) — рисунки и эпизоды целиком на стартовый экран не уходят. Папку проектов для
тестов задаёт `FLOW_LIBRARY_DIR` (абсолютный путь).

**Эскизы.** При сохранении проекта main делает ffmpeg-ом JPEG шириной 320 px из кадра видео (место, где вы остановились,
или 10% длительности, быстрая перемотка, один кадр) и кладёт в `<папка данных>/thumbs/<sha1 пути>.jpg`. Эскиз не тяжелее
60 КБ (иначе сжимается сильнее) и удаляется, когда проект убран из списка. Интерфейс получает эскизы байтами в ответе на
запрос списка (не больше 200 штук) и собирает из них blob-адреса — никакого чтения произвольных файлов; отдельного
протокола для картинок не нужно.

## Видео

Открыть видео: «Просто открыть видео» на стартовом экране, кнопка «Открыть видео» (или `Ctrl+O`), либо перетащить файл на окно.

Поддерживаемые форматы: **MP4 (H.264)**, **WebM**, **MOV**; расширения `.mp4`, `.m4v`, `.mov`, `.webm`, `.mkv`.
Приложение воспроизводит видео встроенным движком Chromium, поэтому файл должен быть в формате, который он умеет
декодировать. Если файл не открывается (например, H.265/HEVC или экзотический кодек), приложение покажет понятное
сообщение. Другие форматы научимся открывать позже. `.mkv` принимается, но играет только если внутри H.264/VP8/VP9.

Те же кадровые шаги есть на кнопках слева от «Пуск» и справа от него. На ползунке громкости стрелки меняют громкость.

### Покадровый переход и формат времени

- Шаг ставит видео ровно на **середину** нужного кадра, поэтому показывается именно он. Перед первым и после
  последнего кадра шаг не идёт. Если держать клавишу, перемотки не копятся в очередь: следующая запрашивается только
  после завершения предыдущей, а нажатия за это время складываются в один переход.
- Клик по текущему времени переключает формат: `ММ:СС.д` ↔ таймкод `ЧЧ:ММ:СС:КК` (КК — номер кадра в секунде,
  без drop-frame). Выбор запоминается.
- Справа от длительности показана частота кадров. Видео в браузере не сообщает её само, поэтому она определяется так:
  1. **Из файла** (MP4, M4V, MOV, в том числе фрагментированный MP4): читаем таблицы контейнера. Для файлов с постоянной
     частотой значение точное; если частота переменная, показано среднее со знаком «≈» (покадровый переход тогда приблизительный).
  2. **Оценка по воспроизведению** (WebM, MKV или если файл не разобрался): после запуска видео частота считается
     по времени показа кадров и уточняется по ходу воспроизведения. Показывается со знаком «≈».
  3. **По умолчанию 25 к/с** со знаком «?», пока ничего другого не известно. Подсказка при наведении объясняет источник.
- Разбор контейнера — одна функция `probeVideo(path)` в `src/main/media/probe.ts`; позже её можно заменить на ffprobe.

## Рисование поверх видео

Слева — инструменты (доступны, когда видео загружено), над видео — панель стиля, справа — свойства выбранного рисунка.

| Инструмент        | Клавиша | Что делает                                                                                |
| ----------------- | ------- | ----------------------------------------------------------------------------------------- |
| Выбор             | `V`     | клик выбирает, перетаскивание двигает; ручки на концах линии/стрелки и углах круга        |
| Стрелка           | `A`     | протяните по картинке; сплошной наконечник растёт вместе с толщиной                       |
| Линия             | `L`     | протяните по картинке                                                                     |
| Круг              | `C`     | эллипс по рамке, слегка залитый тем же цветом (подсветка игрока)                          |
| Текст             | `T`     | клик по картинке, ввод, `Enter` — готово, `Esc` — отмена; двойной клик по тексту — правка |
| Линейка           | `R`     | расстояние по земле в метрах (нужна разметка поля, см. ниже)                              |
| Прожектор         | `S`     | затемняет всё, кроме пятна вокруг игрока (см. «Новые инструменты»)                        |
| Изогнутая стрелка | `B`     | стрелка-дуга (кривая Безье): протяните, затем изогните ручкой посередине                  |
| Перо              | `D`     | линия от руки: упрощается и сглаживается, по желанию со стрелкой на конце                 |
| Зона              | `Z`     | многоугольник по щелчкам, полупрозрачная заливка                                          |
| Связи игроков     | `N`     | ломаная по ногам игроков: линия обороны, расстояния и ширина линии                        |
| Лупа              | `G`     | круг с увеличенным участком кадра (×1.5, ×2, ×3)                                          |

Клавиши работают и в русской раскладке (они привязаны к положению клавиш). Остальное:

- `Shift` при рисовании линии/стрелки — углы кратны 15°; у круга — идеальный круг. Тот же `Shift` работает при
  перетаскивании ручек.
- `Esc` — вернуться к «Выбору», повторное нажатие снимает выделение рисунка; дальше Esc сбрасывает метки «Начало»/«Конец»,
  затем снимает выделение эпизода. `Delete`/`Backspace` — удалить выбранное (рисунок или эпизод — то, что выбрано позже).
- `Ctrl+Z` — отмена, `Ctrl+Y` или `Ctrl+Shift+Z` — повтор (до 100 шагов на каждый вид). Есть и кнопки в панели стиля.
  История общая для рисунков и эпизодов: `Ctrl+Z` отменяет последнее действие любого вида.
- Начало рисования ставит видео на паузу. Слишком короткий «рывок» мышью рисунок не создаёт.
- Стиль: 6 цветов, 3 толщины (для текста — размеры), сплошная/пунктирная линия, подложка под текстом. Изменение
  применяется к выбранному рисунку (с отменой) и ко всем новым. Сразу после рисования новый рисунок выбран, поэтому
  смена цвета перекрасит его; чтобы задать стиль для следующего, нажмите клавишу инструмента (она снимает выделение).

### Когда рисунок виден

У каждого рисунка есть время показа (панель справа, когда рисунок выбран):

- **Отрезок** — виден заданное число секунд от начала (по умолчанию 3 с, но не дальше конца видео; допустимо 0.2–60 с).
- **Только кадр** — виден ровно на одном кадре (при переключении начало «прилипает» к кадру). У такого рисунка есть поле
  **«Стоп-кадр при экспорте, с»** (0.5–30 с, по умолчанию 3): в программе рисунок виден на этом кадре, а в экспортированном
  видео кадр замирает на это время, чтобы рисунок можно было рассмотреть. Правка отменяется как остальные; в старых
  проектах (без этого поля) подставляется 3 с.
- «Начать с текущего момента» переносит начало на текущее время. Рисунок, ставший невидимым при перемотке или
  воспроизведении, перестаёт быть выбранным.
- На таймлайне есть дорожка «Рисунки»: отрезок — полоса цвета рисунка, «только кадр» — тонкая отметка. Клик выбирает
  рисунок и перематывает к его началу.

### Важно

- Координаты рисунков нормализованы по кадру самого видео (0–1 без чёрных полей), поэтому они «приклеены» к картинке
  при любом размере окна. Модель и схемы (zod) — в `src/shared/annotations.ts`: её же будут использовать
  сохранение проекта и экспорт.
- Рисунки сохраняются в файле проекта (см. «Проекты»). Новое видео, «Новый проект» и открытие проекта очищают историю отмены.

## Новые инструменты (этап 15)

Слева инструменты собраны в три группы с разделителями: **основные** (выбор, стрелка, изогнутая стрелка, линия, круг,
текст), **поле и анализ** (линейка, прожектор, зона, связи игроков) и **дополнительные** (перо, лупа). Подсказка у каждой
кнопки показывает текущую клавишу (с учётом переназначения). Все двенадцать кнопок помещаются при минимальной высоте
окна 700 px; если окно ещё ниже, рейка прокручивается. Клавиши новых инструментов (`S`, `B`, `D`, `Z`, `N`, `G`) и
`Enter` («Завершить зону или связи») можно переназначить: «Настройки» → «Горячие клавиши», группа «Рисование».
Новые рисунки работают на экране и (кроме лупы) «На поле» — тогда они лежат на плоскости поля в метрах и привязаны к
разметке (`calibrationId`), время показа у них по умолчанию «Только кадр». Те же `ShapeView`-рисунки получает экспорт.

| Инструмент                  | На экране                                                                                                                                                                                                             | «На поле» (метры)                                                                                                                 |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Прожектор** (`S`)         | клик — высокий эллипс вокруг игрока; можно протянуть рамкой (углы — ручки)                                                                                                                                            | клик — круг радиусом 2.2 м, протяжка задаёт радиус (0.5–15 м), ручка «радиус»                                                     |
| **Изогнутая стрелка** (`B`) | протяжка p1 → p2; средняя ручка стоит на самой кривой — потяните, чтобы изогнуть                                                                                                                                      | кривая задана в метрах, наконечник в плоскости поля, пунктир                                                                      |
| **Перо** (`D`)              | нажать и вести; на отпускании путь упрощается (Рамер — Дуглас — Пекер, допуск 1.8 px) и рисуется сглаженной кривой (Катмулл — Ром); галочка «Стрелка на конце»                                                        | точки переводятся в метры — линия лежит на траве                                                                                  |
| **Зона** (`Z`)              | щелчки по углам; `Enter`, двойной щелчок или щелчок по первой точке замыкают; `Backspace` убирает последнюю точку, `Esc` отменяет; заливка 10–60 %                                                                    | то же + подпись площади в м² (галочка «Площадь на зоне»); площадь считается и для невыпуклых зон                                  |
| **Связи игроков** (`N`)     | щелчки по ногам игроков, `Enter`/двойной щелчок — готово; узлы-маркеры, галочка «Заливка между игроками»                                                                                                              | подписи длин звеньев («9.0 м») и «Ширина линии: 32.4 м» (расстояние между крайними игроками), галочка «Расстояния и ширина линии» |
| **Лупа** (`G`)              | протяните от места, которое увеличиваем, к месту линзы (клик — линза поверх участка); увеличение ×1.5 / ×2 / ×3 в панели; ручки: «источник» (двигает увеличиваемый участок), «линза» (двигает только линзу), «размер» | только на экране (лупа показывает картинку, а не поле)                                                                            |

- **Прожектор.** Затемнение — ползунок 20–80 % (по умолчанию 55 %). Несколько прожекторов, видимых одновременно, дают
  **одну общую маску** (SVG `mask`): затемнение — самое сильное из прожекторов, светлые пятна объединяются; край пятна мягкий.
  Прожектор «на поле» — эллипс на земле и (галочка «Луч вверх», по умолчанию включена) вертикальный полупрозрачный «луч».
  _Приближение:_ высота луча = рост игрока 1.9 м × масштаб в этой точке (пикселей на метр по ширине пятна), поднятая «вверх
  по картинке», сужается кверху (конус); точная вертикаль камеры по четырём точкам земли неизвестна, поэтому луч не
  претендует на метрическую точность. Светлой областью считается пятно вместе с лучом.
- **Правка вершин** (зона, связи): вершины — ручки; `Alt`+щелчок по ребру выбранного рисунка добавляет вершину (её можно сразу
  тащить, всё — один шаг отмены); щелчок по вершине выбирает её (подсвечена), `Delete` убирает **только её** (зона не меньше
  трёх вершин, связи — двух; иначе подсказка). Без выбранной вершины `Delete` удаляет весь рисунок. `Shift` при постановке и
  перетаскивании вершины привязывает направление от соседней вершины (15° на экране, 45° на поле).
- **Панель «Свойства»** (справа) — настоящие, отменяемые настройки: затемнение, увеличение, прозрачность заливки, галочки
  (луч, площадь, стрелка на конце, заливка, подписи). Последнее выбранное значение запоминается для следующих рисунков.
- **Лупа и экспорт.** На экране линза — `canvas`, который рисуется из текущего кадра видео (`requestVideoFrameCallback`),
  поэтому увеличенная картинка идёт вместе с видео. В готовый файл лупа попадает **не** через PNG (в нём нет живого видео), а
  фильтрами ffmpeg: `crop` участка → `scale` → круглая прозрачность (`geq`) → `overlay` на нужное время (или на стоп-кадр);
  рамку, соединительную линию и кружок источника рисует обычная картинка с рисунками поверх линзы. Построение графа —
  `src/main/ffmpeg/loupe.ts` (пиксельная геометрия `src/shared/tools/loupe.ts` общая для экрана и экспорта).
  Прожектор, зона, связи и перо попадают в экспорт обычным путём — через PNG (маска прожекторов рисуется внутри картинки).
- Формат проекта не меняется (версия 1): новые виды рисунков — `spot`, `curve`, `pen`, `zone`, `loupe`, `chain` и на
  поле `pspot`, `pcurve`, `ppen`, `pzone`, `pchain`; новые поля (`dim`, `zoom`, `opacity`, `arrow`, `fill`, `beam`, `showArea`,
  `labels`) имеют значения по умолчанию, поэтому старые проекты открываются как раньше. Код: геометрия и расчёты —
  `src/shared/tools/` и `src/shared/pitch/pitchTools.ts`, интерфейс — `src/renderer/src/features/annotations/`.

## Разметка поля и рисунки на поле

Обычные рисунки лежат поверх картинки и «плоские». Чтобы кольцо вокруг игрока выглядело как круг на траве, а стрелка
сужалась вдаль, приложению нужно знать, как поле выглядит в кадре. Для этого поле **размечается**: вы отмечаете на кадре
несколько известных точек поля (углы штрафной площади и т. п.), а программа считает перспективу (гомографию «поле в
метрах → кадр») и дальше рисует на плоскости поля.

### Как разметить поле

1. Остановите видео на кадре, где хорошо видны линии, и нажмите **«Разметить поле»** (кнопка над видео, клавиша `P`;
   клавишу можно сменить: «Настройки» → «Горячие клавиши», группа «Рисование»). Видео встаёт на паузу, картинка сдвигается
   вправо, слева открывается панель разметки.
2. Выберите **шаблон**: штрафная площадь (слева/справа), вратарская площадка (слева/справа), половина поля (слева/справа)
   или «Свой прямоугольник» (любые четыре угла известного размера в метрах). Размеры поля — длина 90–120 м (по умолчанию 105) и ширина 45–90 м (68); площади и круги считаются по правилам ФИФА (штрафная 16.5 × 40.32 м, вратарская 5.5 × 18.32 м,
   пенальти 11 м, центральный круг 9.15 м).
3. На схеме подсвечена **следующая точка**; щёлкайте по ней на видео. Точку можно сразу подправить, не отпуская кнопку;
   рядом с курсором появляется **лупа** (увеличенный кусочек кадра ×4). Отмеченную точку можно перетащить, `Alt+стрелки`
   сдвигают выбранную на 1 пиксель (с `Shift` — на 5), `Backspace` убирает последнюю. Точки можно ставить и за краем
   кадра (если угол поля не виден).
4. Как только отмечены 4 точки, поверх кадра показываются **линии поля** в найденной перспективе (белые, полупрозрачные):
   видно, совпали ли они с линиями на видео. Показывается точность («Точность: 1.8 px — хорошо» / «терпимо» / «плохо,
   проверьте точки»). Четыре точки всегда дают нулевую ошибку, поэтому для проверки добавьте ещё точки: **«+ точка»** →
   выберите точку на схеме (углы вратарской, пенальти, штанги, концы штрафной дуги) → щёлкните по ней на видео.
   Ошибки объясняются по-русски: точки в неверном порядке, три на одной прямой, слишком близко друг к другу.
5. **«Сохранить разметку»** (или `Enter`) или **«Отмена»** (`Esc`). Пока идёт разметка, остальные клавиши (кроме шагов
   по кадрам) не действуют.

Разметок может быть много (поле видно не на всех кадрах и камера двигается). В правой панели — список разметок: время
кадра, шаблон, точность; клик — перейти к кадру разметки, карандаш — поправить точки (рисунки на поле пересчитываются
вживую), корзина — удалить (отменяется). Флажок **«Показать сетку поля»** рисует линии поля поверх видео, пока видео
рядом с кадром разметки (до 1 с). Разметки входят в общую историю отмены вместе с рисунками и эпизодами.

### Рисунки на поле

Когда есть хотя бы одна разметка, над видео включается переключатель **«На поле»** (по умолчанию включён, выбор
запоминается). Тогда инструменты рисуют на плоскости поля: курсор переводится в метры по перспективе, рисунок хранится в
метрах и привязан к разметке, поэтому при правке точек разметки рисунок остаётся на месте поля. Выключите «На поле» —
инструменты рисуют обычные плоские рисунки.

- **Круг** — кольцо на траве: щелчок ставит кольцо радиусом 1 м (вокруг игрока), перетаскивание задаёт радиус в метрах.
  Мягкая заливка внутри. Превращается в эллипс по перспективе.
- **Стрелка** и **линия** — полосы постоянной ширины в метрах: вдаль сужаются, наконечник лежит в плоскости поля.
  Линия бывает пунктирной.
- **Текст** — подпись, стоящая вертикально над выбранной точкой земли (размер на экране, не сужается).
- **Линейка** (`R`) — линия по земле с засечками на концах и подписью «23.4 м» (расстояние считается в метрах поля).
  Инструмент доступен, только когда есть разметка.
- `Shift` привязывает направление к осям поля: 0°, 45°, 90° (а не к экрану); у кольца — радиус кратен 0,5 м.
- Выбор, ручки (концы линии, радиус кольца) и перемещение тоже работают в метрах: рисунок едет по земле.
- Время показа у рисунка на поле по умолчанию «Только кадр» (камера обычно двигается), его можно сменить на «Отрезок».
- В панели над видео показано, какая разметка действует («Разметка поля: 00:12.3 (2.1 с назад)»): та, что ближе по времени
  (с любой стороны). Если разметки нет, «На поле» и «Линейка» недоступны («Сначала разметьте поле»).
- Рисунки на поле попадают в экспорт тем же путём, что и обычные (с перспективой, стоп-кадрами и т. д.).

### Ограничение: камера двигается

Разметка относится к **одному кадру**. Автоматического слежения за камерой пока нет, поэтому, если камера сдвинулась, рисунок на
поле «отстанет» от линий. Приложение честно предупреждает: когда рисунок показан дальше чем 1 с от кадра разметки, он
рисуется бледнее, а в панели справа у него написано «Камера могла сдвинуться — проверьте разметку». Для длинных отрезков
размечайте поле заново на нужных кадрах и рисуйте от ближайшей разметки. Удалили разметку — её рисунки на поле скрываются
(вернуть можно отменой) и в файл не пишутся.

### Как это устроено

Математика — в `src/shared/pitch/` (чистые функции, покрыты тестами): нормализованный DLT с нормировкой Хартли (метод
Якоби для собственных векторов, без внешних библиотек), проверки вырожденности (меньше 4 точек, три на одной прямой, малая
площадь, плохая обусловленность, порядок точек, точки за камерой), проектор «поле ↔ кадр» с отсечением там, где проекция
невозможна (фигуры в метрах обрезаются до проекции), адаптивная плотность дуг и окружностей. Интерфейс разметки —
`src/renderer/src/features/pitch/`. Рисунки на поле проходят тот же конвейер `ShapeView`, что и обычные, поэтому экспорт
получает перспективу «бесплатно». В файле проекта хранятся только точки разметок (`calibrations`), матрица пересчитывается
при загрузке.

Тестовое видео `tests/fixtures/pitch.mp4` (поле в перспективе, 3 с) и `pitch.json` (точная гомография и опорные точки)
делает `node scripts/make-fixtures.mjs pitch` (нужны Google Chrome и ffmpeg-static): кадр рисуется в Chrome по известной
камере и кодируется ffmpeg.

## Рисунки под игроками (этап 16a)

Как в телевизионной телестрации: кольцо, стрелка или зона лежат **на траве**, а игроки их **закрывают** — рисунок
виден только там, где в кадре газон. Это работает и на экране, и в готовом видео.

- Переключатель **«Под игроками»** есть в панели справа (у выбранного рисунка) и в панели стиля (для новых рисунков;
  выбор запоминается отдельно для рисунков «На поле» и на экране). По умолчанию «под игроками» лежат все рисунки на поле:
  кольцо, стрелки, линия, перо, зона, связи, прожектор (его кольцо и круг на земле) и линия линейки. Рисунки на экране
  по умолчанию лежат поверх игроков, но их тоже можно положить под игроков. **Подписи всегда остаются сверху**:
  текст, «23.4 м» у линейки, площадь зоны, длины звеньев, «Ширина линии», лупа. Старые проекты открываются: поля
  `underPlayers` у рисунков нет, значение берётся по виду рисунка.
- **Затемнение прожектора** — эффект на весь кадр, поэтому оно всегда сверху (не ключуется); луч прожектора на траве
  тоже сверху.
- Кнопка **«Газон»** в панели стиля открывает настройки: цвет газона определяется сам (по нижним 60 % кадра, медиана
  «зелёных» пикселей: линии, игроки и тени в неё не попадают); если программа ошиблась, нажмите **«Пипетка»** и щёлкните
  по траве на видео. **«Чувствительность»** — насколько цвет может отличаться от газона и всё ещё считаться газоном,
  **«Мягкость края»** — ширина плавного перехода между рисунком и игроком. **«Показать маску»** показывает вместо видео
  саму маску: белое — газон, где рисунки видны, чёрное — игроки, линии и всё остальное (подберите ползунки так, чтобы
  игроки были чёрными); пока маска включена, в углу картинки висит плашка «Маска газона · выключить».
  **«Сбросить (авто)»** возвращает обычные настройки и снова ищет цвет по кадру. Настройки хранятся в проекте (`grassKey`:
  `color`, `similarity` 0.01–0.5, `blend` 0–0.3, `auto`); пока вы их не меняли, в файле их нет.

### Как это устроено

Одно определение ключа для экрана и экспорта — копия фильтра `chromakey` из ffmpeg (`libavfilter/vf_chromakey.c`):
расстояние до цвета ключа по цветности (U, V), среднее по окну 3×3, `similarity` и `blend`. TS-функция
`chromakeyAlpha` / `grassMask` (`src/shared/grassKey.ts`) сверяется с самим ffmpeg: на случайных плоскостях U/V ошибка 0/255
(тест `src/main/ffmpeg/grassKey.test.ts`). Цвет кадра для ключа переводится в U/V формулами JPEG (полный диапазон) —
теми же, которыми ffmpeg переводит цвет ключа, поэтому цвет, выбранный пипеткой, и цвет, который получает ffmpeg, совпадают.

- **Экран.** Между видео и слоем рисунков лежит холст WebGL2 (`src/renderer/src/features/under/`): кадр видео
  загружается в текстуру на каждый показанный кадр (`requestVideoFrameCallback`; когда «под игроками» ничего не нужно,
  слой простаивает), шейдер считает маску по формуле ffmpeg, рисунки умножаются на маску. Растр рисунков (SVG → холст
  размером с картинку × `devicePixelRatio`) обновляется только при изменении набора, геометрии, стиля или размера.
  Перерисовок React на кадр нет, всё делает видеокарта. Если WebGL2 недоступен, такие рисунки рисуются поверх игроков,
  а на экране один раз появляется уведомление; готовое видео от этого не страдает. Чтобы WebGL мог читать видео,
  элемент `<video>` загружается в режиме CORS (`crossorigin`), а протокол `flow-media://` отвечает
  `Access-Control-Allow-Origin: *`; файлы по-прежнему выдаёт только реестр.
- **Экспорт.** Для набора рисунков `renderOverlayImages` делает до двух PNG: «поверх всего» (`over`) и «под игроками»
  (`under`). В графе ffmpeg кадр делится на три копии: основа, копия под рисунки и источник маски; `under`-PNG
  накладывается на копию теми же окнами `enable`, маска строится из кадра
  (`format=rgb24,scale=out_range=pc,format=yuva444p,chromakey,alphaextract,negate`), `maskedmerge` вливает копию в основу
  по маске, затем накладываются PNG «поверх всего». Лупа делается **после** слияния (линза увеличивает уже готовую
  картинку), стоп-кадры и подборки работают так же, как и без «под игроками». Основа в местах без рисунков не меняется.

### Ограничения

- Ключ смотрит только на **цвет газона**. Рисунок пропадает не там, где надо, если игрок одет в зелёное, рядом зелёные
  рекламные щиты или цвет игрока близок к газону. Наоборот, **белая и серая форма** почти нейтральна по цвету, и при большой
  чувствительности такой игрок «сливается» с газоном; линии разметки нейтральны и тоже скрывают рисунок (это сделано
  сознательно). Сначала уменьшите «Чувствительность», потом выберите цвет пипеткой.
- **Полосатый и вытоптанный газон**: полосы различаются яркостью, а не цветом, и ключ их не различает; а вот выжженные
  жёлтые и вытоптанные коричневые участки могут не считаться газоном — рисунок в этих местах будет скрыт. Повысьте
  «Чувствительность» или выберите цвет пипеткой по такому участку.
- **Тени** на траве почти зелёные — рисунок в тени виден; очень тёмные тени теряют цветность и могут скрывать рисунок.
- Один цвет ключа на видео. Если освещение сильно меняется (солнце и тень на половине поля), цвет берётся по текущему
  кадру (или пипеткой), проверяйте маску для разных частей матча.
- Лупа на экране показывает кадр без рисунков «под игроками»; в готовом видео линза увеличивает кадр вместе с ними.
- На самом крайнем ряду пикселей кадра ffmpeg читает память за пределами картинки, поэтому там его результат не
  определён; экран и готовое видео могут отличаться только на этом ряду.
- Кадр в WebGL (Chrome) и кадр в ffmpeg переводятся из YUV в RGB по одной и той же разметке цвета в файле; у файлов без
  разметки возможна небольшая разница оттенков — её закрывает «Чувствительность».

## Разметка эпизодов

Эпизод — отрезок видео с тегом («Атака», «Гол» и т. д.). Теги и список эпизодов — в правой панели.

Два способа разметки (работают одновременно):

- **Быстрый тег.** Нажмите клавишу тега (или кнопку) — создаётся эпизод `[t − до, t + после]` вокруг текущего момента,
  обрезанный по границам видео. Для стандартных тегов «до» и «после» по 5 секунд. Воспроизведение **не останавливается**,
  так что размечать можно «на ходу». Подтверждение: вспышка кнопки и сообщение «Эпизод «Атака» 00:12.0–00:22.0».
- **Точная разметка.** `I` — поставить «Начало» на текущее время, `O` — «Конец» (метки видны на линейке таймлайна и в
  панели тегов). Когда обе метки стоят (начало раньше конца), следующий тег (клавиша или кнопка) создаёт эпизод ровно
  между ними и сбрасывает метки. Если конец раньше начала или отрезок короче 0.2 с, эпизод не создаётся, а приложение
  объясняет почему. `Esc` сбрасывает метки (после того как инструмент рисования и выделение рисунка уже сняты).

Стандартные теги и клавиши (русская раскладка не мешает: клавиши привязаны к положению на клавиатуре):

| Клавиша | Тег               | Клавиша | Тег    |
| ------- | ----------------- | ------- | ------ |
| `1`     | Атака             | `6`     | Удар   |
| `2`     | Оборона           | `7`     | Гол    |
| `3`     | Переход в атаку   | `8`     | Потеря |
| `4`     | Переход в оборону | `9`     | Отбор  |
| `5`     | Стандарт          |         |        |

Список «Эпизоды» (по порядку начала): клик по строке — перейти к началу (воспроизведение не меняется), двойной клик —
играть с начала; фильтр по тегам (кнопки-«чипы»); корзина или `Delete` — удалить. У выбранного эпизода можно взять
начало/конец с текущего времени и написать заметку (до 500 символов). На таймлайне есть дорожка «Эпизоды»: полосы цвета
тега (пересекающиеся — на разных строках), клик выбирает эпизод и ведёт к началу.

### Оценки эпизодов

У каждого эпизода есть оценка «хорошо» или «плохо» (взаимоисключающие, по умолчанию её нет) и отдельный флаг «разобрать»
(от оценки не зависит). Всё это хранится в файле проекта (`rating`: `good` / `bad` / `null`, `review`: `true` / `false`);
в старых проектах этих полей нет — при открытии подставляются «без оценки» и «не разбирать».

- **Кнопки в строке эпизода:** три значка — «палец вверх» (хорошо, зелёный), «палец вниз» (плохо, красный), «лупа»
  («разобрать», янтарный). Подсказки с клавишами: «Хорошо (=)», «Плохо (-)», «Разобрать (/)». Клик включает, повторный клик
  по включённой оценке снимает её, «плохо» при включённом «хорошо» переключает. Оценка — обычное изменение проекта:
  отменяется через `Ctrl+Z`, помечает проект несохранённым.
- **Клавиши** (группа «Эпизоды» в настройках, переназначаются): `=` — хорошо, `-` — плохо, `/` — «разобрать». Применяются к
  выбранному эпизоду, а если выбора нет — к **последнему созданному**; если эпизодов нет, коротко подсказывают об этом.
  Клавиши привязаны к положению на клавиатуре (работают в любой раскладке).
- **Подсказка после тега** («Эпизод «Атака» 00:12.0–00:22.0») тоже содержит три значка: сразу после разметки эпизод можно
  оценить кликом, пока подсказка видна (она висит чуть дольше обычного).
- **Таймлайн:** на полосе эпизода слева появляются маленькие значки оценки (если полоса достаточно широка).
- **Фильтр по оценке** в панели «Эпизоды»: чипы-значки «хорошо», «плохо», «разобрать» и «Без оценки» (значки — векторные, не эмодзи) с числом эпизодов. Несколько
  выбранных чипов объединяются по «или», с фильтром по тегам — по «и»; «Показать все» сбрасывает оба фильтра. Фильтр
  учитывают полосы таймлайна (остальные тускнеют), «Видимые по фильтру» в экспорте и «Учитывать фильтр эпизодов» в статистике.

Имя и цвет тега копируются в эпизод, поэтому смена тега в настройках уже созданные эпизоды не меняет. Модель и схемы (zod)
— `src/shared/episodes.ts`. Эпизоды сохраняются в файле проекта (см. «Проекты»).

## Проекты

Проект — это видео, ваши рисунки и эпизоды. Он хранится в файле `.flowproj`; само видео в файл не копируется (в нём только путь).

- Меню **«Проект»** слева вверху: «Новый проект» (окно с названием, типом и видео), «Открыть проект…», «Последние проекты»
  (до 10; исчезнувшие файлы из списка пропадают), «Сохранить», «Сохранить как…», «Свойства проекта…», «Главная».
  Список всех проектов — на стартовом экране (см. выше). Рядом с названием проекта точка «•» значит, что есть несохранённые
  изменения; в заголовке окна то же самое показывает звёздочка: `FlowAnalyzer — Финал*`.
- Клавиши (все переназначаются в «Настройки» → «Горячие клавиши», группа «Проект»): `Ctrl+S` сохранить, `Ctrl+Shift+S`
  сохранить как, `Ctrl+Shift+O` открыть проект, `Ctrl+N` новый проект (окно создания), `Ctrl+H` на главную. `Ctrl+O`
  по-прежнему открывает видео.
- «Несохранённым» проект становится от любого изменения рисунков и эпизодов (в том числе отмены и повтора).
  Перемотка, воспроизведение, выбор и инструменты проект не меняют.
- Если проект не сохранён, `Ctrl+N`, `Ctrl+H`, открытие другого видео, открытие другого проекта и закрытие окна спрашивают:
  «Сохранить изменения в проекте?» — «Сохранить», «Не сохранять», «Отмена».
- **Видео не нашлось.** При открытии проекта видео ищется по сохранённому пути, затем по относительному пути от папки
  проекта (так можно переносить проект вместе с видео). Если его нет нигде, приложение предлагает «Указать видео…» или отменить.
  Если размер выбранного файла отличается от сохранённого, будет предупреждение (открыть всё равно можно). После указания
  нового пути проект помечается несохранённым, чтобы новый путь можно было записать.
- **Ошибки.** Повреждённый файл, неверные данные, файл слишком большой (больше 20 МБ) или созданный более новой версией
  программы — понятное сообщение с подробностями (свёрнуты), а текущая работа не меняется.
- **Восстановление после сбоя.** Пока есть несохранённые изменения, приложение раз в 2 минуты пишет копию работы в
  `<папка данных>/recovery/` (сам проект при этом не трогается). После аварийного завершения при следующем запуске вверху
  появится плашка «Найдена несохранённая работа от …» с кнопками «Восстановить» и «Удалить». Копия удаляется после
  сохранения, при «Не сохранять» и при «Удалить». Для тестов интервал можно изменить переменной `FLOW_AUTOSAVE_MS`.
- **Файл `.flowproj` в проводнике.** Установщик связывает расширение `.flowproj` с FlowAnalyzer: двойной щелчок открывает
  проект. Если программа уже запущена, файл откроется в её окне (второе окно не создаётся). Путь можно передать и в
  командной строке: `FlowAnalyzer.exe "C:\Матчи\Финал.flowproj"`.

### Формат файла

`.flowproj` — обычный UTF-8 JSON, схема (zod) — `src/shared/project.ts`:

```json
{
  "format": "flowanalyzer-project",
  "version": 1,
  "createdAt": "2026-01-01T10:00:00.000Z",
  "updatedAt": "2026-01-02T10:00:00.000Z",
  "appVersion": "0.6.0",
  "video": {
    "path": "абсолютный путь",
    "relativePath": "../video/match.mp4",
    "fileName": "match.mp4",
    "sizeBytes": 12345,
    "fps": 25,
    "fpsSource": "container",
    "duration": 5400
  },
  "annotations": [],
  "calibrations": [],
  "grassKey": { "color": "#2a7d3e", "similarity": 0.07, "blend": 0.05, "auto": false },
  "episodes": [],
  "tags": [],
  "ui": { "lastTime": 4.5 },
  "meta": { "title": "Финал", "type": "match", "date": "2026-05-17", "notes": "…" }
}
```

`meta` (необязательно) — описание проекта: `title` (1–80 символов), `type` (`match` / `training` / `scouting` / `other`), `date`
(`ГГГГ-ММ-ДД`, необязательно), `notes` (до 500 символов, необязательно). Старые файлы без `meta` открываются: название — имя
файла, тип — «Другое». `video.duration` — длительность видео, если была известна при сохранении (нужна для карточки).
`annotations` и `episodes` — те же модели, что в интерфейсе (координаты рисунков нормализованы по кадру; у рисунков есть `space`: `screen` — плоский рисунок, `pitch` — рисунок на поле в метрах с `calibrationId`; у старых рисунков `space` нет, подставляется `screen`); `grassKey` (необязательно) — настройки ключа «газон» для рисунков «под игроками»; у рисунков есть необязательное `underPlayers` (нет — значение по виду рисунка); `calibrations` (необязательно, по умолчанию пусто) — разметки поля: время кадра, размеры поля, шаблон и пары «точка поля в метрах ↔ точка кадра (0–1)»; `tags` — снимок
тегов на момент сохранения (теги из настроек плюс теги, оставшиеся только в эпизодах); при открытии проекта настройки
пользователя не меняются. Пределы: не больше 10 000 рисунков и 10 000 эпизодов, файл не больше 20 МБ. Файл более новой
версии не открывается («Файл создан более новой версией FlowAnalyzer»); для будущих версий есть `migrateProject`.
Запись атомарная: сначала временный файл рядом, потом переименование — прежний файл остаётся целым, если запись прервалась.
Список недавних проектов лежит в `recent.json` в папке данных приложения.

Безопасность: путь к файлу проекта выбирает пользователь (диалог, список недавних, двойной щелчок или командная строка);
main не открывает и не перезаписывает файлы, которых приложение не выдавало само. Интерфейс не знает путь к видео:
при сохранении он присылает только идентификатор выданного видео. Заголовок окна задаёт только main.

## Экспорт клипов

Кнопка «Экспорт клипов» в заголовке панели эпизодов (выключена, пока не открыто видео) или `Ctrl+E` (клавишу можно сменить в
настройках: группа «Экспорт»). Несохранённый проект экспорту не мешает.

В окне выбирается:

- **Какие эпизоды**: «Видимые по фильтру (N)» (пункт появляется, когда включён фильтр по тегам), «Все (N)» или «Выбрать вручную»
  (список с цветами тегов, «Выбрать все» / «Снять все»), а также **«Всё видео целиком»** — один файл из всего видео
  (длительность от 0 до конца). Последний пункт работает и без эпизодов: тогда он выбран сам, а режимы «Отдельные файлы» /
  «Одна подборка» и запас по краям скрыты.
- **Что получится**:
  - **Отдельные файлы** — по одному MP4 на эпизод в выбранную папку (диалог выбора папки открывает программа). Имена
    `NNN_Тег_ММ-СС.mp4` (номер по порядку в матче, тег и время начала эпизода; кириллица сохраняется, символы, запрещённые в
    Windows, убираются). Существующие файлы не перезаписываются: добавляется « (2)», « (3)»…
  - **Одна подборка** — все выбранные эпизоды подряд (в порядке времени в матче) в одном MP4; имя по умолчанию
    `<проект>_подборка.mp4` (если проект не сохранён — по имени видео). Если выбрать уже существующий файл, система спросит о замене.
- **Точность**:
  - **Точно** (по умолчанию) — перекодирование H.264 (`libx264`, `-preset veryfast -crf 20`, `yuv420p`, звук AAC 160 кбит/с,
    `+faststart`). Начало и конец клипа совпадают с эпизодом с точностью до кадра.
  - **Быстро (без перекодирования)** — копирование потоков: почти мгновенно и без потери качества, но начало и конец
    сдвигаются к ближайшему ключевому кадру (обычно на секунду-две, иногда больше). Для подборки недоступно: куски из разных мест
    нельзя надёжно склеить без перекодирования (в окне это объяснено).
- **Запас по краям** — от 0 до 10 секунд добавляется до и после каждого эпизода (обрезается границами видео).
- **Рисунки** — переключатель «С рисунками» (см. ниже). Включён сам, если хоть один рисунок попадает в выбранные отрезки;
  если рисунков там нет, выключен и объяснён. В режиме «Быстро» недоступен (копирование потока не умеет рисовать) — нужно
  выбрать «Точно»; запрос с рисунками всегда уходит с перекодированием. В сводке «длительность» уже **с учётом стоп-кадров**.

Во время экспорта окно остаётся открытым: общий прогресс и прогресс текущего клипа, имя файла, прошедшее и оценка оставшегося
времени, кнопка «Остановить экспорт». Отмена убирает недописанный файл; в режиме «Отдельные файлы» уже готовые клипы остаются.
Если часть клипов не получилась, остальные всё равно создаются, а ошибки показываются списком (с подробностями ffmpeg).
Закрытие окна программы во время экспорта спросит, остановить ли его. После окончания «Открыть папку» показывает в проводнике
файл, созданный этим экспортом.

Как это устроено: `src/main/ffmpeg/` — путь к ffmpeg (`path.ts`), аргументы (`args.ts`), запуск процесса с прогрессом, отменой и
таймаутом зависания (`runner.ts`), задание экспорта (`job.ts`), имена файлов (`names.ts`). ffmpeg запускается массивом
аргументов без оболочки; видео задаётся идентификатором (интерфейс путей не присылает); запрос проверяется схемой zod
(`src/shared/export.ts`) и границами по реальной длительности видео (`src/shared/exportRanges.ts`). Результат пишется во
временный файл `*.part` рядом и переименовывается после успеха. Для точного режима `-ss` и `-t` стоят перед `-i`: быстрый
переход к ключевому кадру, а точная подрезка до кадра делается при перекодировании. Подборка собирается одним вызовом ffmpeg:
`trim`/`atrim` каждого эпизода и `concat` (граф лежит во временном файле `-filter_complex_script`, чтобы не упереться в предел
длины командной строки); всё до первого эпизода пропускается быстрой перемоткой.

Скорость (12 потоков процессора, синтетическое видео 1080p, 25 к/с, на реальных матчах медленнее в 1,5–3 раза):
перекодирование ≈ 13× быстрее реального времени (60 секунд клипов — около 5 секунд), копирование — мгновенно, подборка из
90-минутного матча читает видео от первого до последнего эпизода (декодирование ≈ 50× реального времени), то есть
несколько минут.

### Экспорт с рисунками

Рисунки наносятся на видео в родном разрешении файла и выглядят так же, как на экране (толщина линий, наконечники стрелок,
подложка и шрифт текста): интерфейс рисует их тем же кодом (`ShapeView`), переводит в прозрачные PNG размером
`videoWidth × videoHeight` и отправляет в main отдельным вызовом (двоичные данные, не base64). Дальше FFmpeg накладывает
картинки фильтром `overlay`.

- **Рисунки-отрезки** (`src/shared/exportOverlays.ts`): внутри экспортируемых отрезков время делится на интервалы, на которых
  набор видимых рисунков не меняется; на каждый разный набор — одна картинка с этими рисунками (в порядке слоёв), поэтому
  наложений мало, а одинаковые наборы в разных местах используют одну и ту же картинку. Рисунок виден на кадре, если на
  середину кадра он «виден» на экране; рисунок, частично выходящий за отрезок, обрезается по нему.
- **Стоп-кадры** («Только кадр»): кадр с рисунком замирает на заданное время. Рисунки одного кадра дают **один** стоп-кадр
  длиной в наибольшее из их значений, и в нём видны все рисунки этого кадра и рисунки-отрезки, видимые в этот момент. Стоп-кадр
  вставляется между частями видео (видео удлиняется на его длину); звук на это время — тишина, поэтому звук и картинка не
  расходятся (проверено: «писк» на известной секунде остаётся на месте ±1 кадр; длительности дорожек совпадают).
  Длина стоп-кадра округляется до целого числа кадров (при 25 к/с 1.5 с = 37.5 кадра → 38).
- Работает для «Отдельных файлов» (у каждого файла свои рисунки и стоп-кадры), «Одной подборки» и «Всего видео целиком».
- Граф фильтров собирает чистая функция `src/main/ffmpeg/drawGraph.ts` (кладётся в `-filter_complex_script`); пути картинок идут
  входами `-i` массивом аргументов, в графе путей нет — кириллица и пробелы в путях не требуют экранирования.
- **Проверки в main**: PNG принимается, только если подпись верна, первый блок IHDR, в конце IEND, размеры из заголовка
  равны размеру видео; не больше 8 МБ на картинку, 300 картинок и 300 МБ всего. Картинки пишутся в отдельную временную
  папку `flow-overlays-*`; она удаляется при любом исходе (успех, ошибка, отмена, выход из программы), а остатки после
  аварийного завершения чистятся при следующем запуске.
- Ход работы: сначала «Подготовка рисунков…» (её можно остановить), затем обычный прогресс; общая длительность в прогрессе
  учитывает стоп-кадры.

**Ограничения.** Рисунки наносятся только с перекодированием. Больше 300 разных наборов рисунков (разных сочетаний видимых
рисунков) за один экспорт — отказ с советом экспортировать по частям. Картинка с рисунками — на каждый набор в размер
видео, поэтому при очень большом видео (4K) и сотнях наборов подготовка занимает заметное время (десятки миллисекунд на
картинку) и место во временной папке. Частота кадров для стоп-кадров берётся из проекта (из файла, если определилась точно);
для видео с переменной частотой кадров стоп-кадр может оказаться на соседнем кадре. Тень вокруг рисунков пересчитана под
размер кадра (на экране она фиксированная), поэтому на очень большом видео она относительно чуть тоньше или толще.

**Новые рисунки (этап 15).** Прожектор, зона, связи и перо идут тем же путём (PNG). Лупа добавляет в граф фильтров
цепочку «вырезать → увеличить → круг → наложить» на каждую лупу (на время её показа или на стоп-кадр); для этого в запросе
на экспорт есть список луп (`drawings.loupes`: номер рисунка, положение, источник, радиус, увеличение). Тест на настоящем
ffmpeg (`src/main/ffmpeg/tools.drawn.test.ts`) сравнивает пиксели линзы с увеличенным участком исходного кадра, снаружи
линзы кадр остаётся прежним; затемнение прожектора проверяется по яркости углов. Лупа (`geq` над линзой каждого кадра) чуть
замедляет экспорт — тем сильнее, чем больше линза.

### FFmpeg и лицензия

Для вырезания клипов используется FFmpeg из npm-пакета [`ffmpeg-static`](https://github.com/eugeneware/ffmpeg-static)
(сборка gyan.dev 6.1.1, **лицензия GPL v3**, исходный код: <https://github.com/FFmpeg/FFmpeg/commit/e38092ef93>,
<https://ffmpeg.org/download.html#get-sources>). В готовой программе `ffmpeg.exe` лежит распакованным в
`resources/app.asar.unpacked/node_modules/ffmpeg-static/` (из архива `app.asar` запустить программу нельзя; путь получается
заменой `app.asar` на `app.asar.unpacked`), а текст лицензии и ссылки на исходный код — в `resources/licenses/ffmpeg-LICENSE.txt`
(исходник — `licenses/ffmpeg-LICENSE.txt` в репозитории). FFmpeg запускается отдельным процессом и не связан с кодом FlowAnalyzer.

## Статистика

Кнопка «Статистика» в верхней панели (выключена, пока не открыто видео) или `Ctrl+I` (клавишу можно сменить в настройках:
группа «Анализ»). Без эпизодов окно честно пишет «Пока нет эпизодов — отметьте их тегами, и здесь появится статистика».
Esc закрывает окно, фокус не выходит за его пределы.

В окне:

- **Показатели:** число эпизодов; время в эпизодах (и % видео); число тегов; средняя длительность; % хороших (с числом
  «хорошо» и «плохо»). Время в эпизодах считается
  по объединению отрезков: если эпизоды перекрываются, перекрытие учитывается один раз, поэтому процент видео не бывает выше 100.
  Эпизоды, выходящие за конец видео, обрезаются по его границам.
- **Таблица по тегам:** цвет, тег, число эпизодов, время всего, среднее, % эпизодов, % времени (доля среди суммарного времени
  всех тегов), затем оценки: число «хороших», «плохих», «разобрать» (столбцы-значки) и **% хороших** = хорошо / (хорошо + плохо),
  «—», если оценённых эпизодов нет. Сортировка — клик по заголовку столбца. **Клик по строке** включает этот тег как фильтр в списке эпизодов
  (как кнопка-чип) и закрывает окно.
- **Диаграмма «Эпизоды по тегам»:** горизонтальные столбцы в цветах тегов, значения подписаны.
- **Диаграмма «Эпизоды по ходу матча»:** столбики по отрезкам времени, внутри слои по тегам. Эпизод считается в том отрезке,
  где он **начинается**. Ось — время матча (00:00, 05:00…). При наведении или фокусе — подсказка с диапазоном и числом
  эпизодов по тегам; стрелки ← → переходят между столбцами. **Клик по столбцу** (или Enter) перематывает видео к началу отрезка
  и закрывает окно. Размер отрезка: «Авто», 1, 5, 10 или 15 минут.
  Правило «Авто»: самый крупный размер из 5 мин / 2 мин / 1 мин / 30 с / 15 с / 10 с / 5 с / 2 с / 1 с, при котором получается
  не меньше четырёх отрезков. Видео от 20 минут — по 5 минут, 10-минутное — по 2 минуты, 4-секундное — по 1 секунде.
- **«Учитывать фильтр эпизодов»:** переключатель появляется, когда в списке эпизодов выбран фильтр (по тегам и/или по
  оценкам); тогда статистика и CSV считаются только по видимым эпизодам.

Названия и цвета: если тег ещё есть в настройках — берутся оттуда (переименованный тег виден в статистике под новым именем),
иначе — по самому свежему эпизоду. Цвета тегов задаёт пользователь, поэтому диаграммы не опираются только на цвет: есть
легенда, подписи у столбцов и таблица; цвет, почти сливающийся с фоном (контраст меньше 3:1), получает тонкую обводку.

### Выгрузка CSV

Кнопка «Выгрузить CSV» спрашивает место (по умолчанию «<проект или видео>_статистика.csv» рядом с видео) и сохраняет **один файл**
для Excel (столбцы «Оценка» — Хорошо / Плохо / «—» и «Разобрать» — да / нет есть в списке эпизодов, а счётчики и «Хороших, %» — в таблице по тегам): UTF-8 с BOM, разделитель `;`, десятичная запятая, строки через CRLF. В файле два раздела с пустой строкой между ними:

```
Статистика по тегам
Тег;Эпизодов;Время всего, с;Средняя длительность, с;Доля эпизодов, %;Доля времени, %;Первое начало;Последнее начало;Хорошо;Плохо;Разобрать;Хороших, %
Атака;2;2,0;1,0;66,7;57,1;00:00.5;00:02.0;1;1;1;50,0

Эпизоды
№;Тег;Начало;Конец;Длительность, с;Оценка;Разобрать;Заметка
1;Атака;00:00.5;00:01.5;1,0;Хорошо;нет;'=1+1
```

Поля с `;`, кавычкой или переносом строки берутся в кавычки (кавычка внутри удваивается). Защита от CSV-инъекций: текстовая
ячейка, начинающаяся с `=`, `+`, `-`, `@`, табуляции или возврата каретки, получает впереди апостроф (`'=1+1`), чтобы Excel не
выполнил её как формулу. После сохранения внизу окна появляется «Сохранено: <имя файла>» и кнопка «Показать в папке» (она
открывает именно этот файл).

Расчёт — чистые функции в `src/shared/stats.ts`. Интерфейс присылает в main **структурированные данные** (не готовый CSV),
`src/shared/statsExport.ts` — схема zod (не больше 10 000 эпизодов и 200 тегов, длины строк, неотрицательные числа, конец не
раньше начала, лишние поля отклоняются); CSV собирает `src/main/stats/csv.ts`, запись атомарная (временный файл и
переименование).

## Настройки

Кнопка-шестерёнка в верхней панели или `Ctrl+,`. Изменения применяются по «Сохранить», «Отмена» (или `Esc`) их отбрасывает.

- **Теги:** название (до 40 символов), цвет (образцы или `#rrggbb`), секунды «до» и «после» (0–60), клавиша, порядок
  (стрелки вверх/вниз), добавление (до 30 тегов) и удаление (с подтверждением в окне), «Сбросить к стандартным».
- **Горячие клавиши:** все команды по группам. «Изменить» — нажмите новое сочетание (`Esc` — отмена, `Backspace` — снять
  клавишу). Если сочетание уже занято, приложение покажет чем, и предложит «Заменить». «Сбросить» — вернуть стандартную
  клавишу команды, «Сбросить все» — все. Команде назначается одно сочетание; `Tab` назначить нельзя.

Где хранятся: файл `settings.json` в папке данных приложения (`%APPDATA%\FlowAnalyzer`). В нём только изменённые
клавиши и список тегов. Запись атомарная (временный файл и переименование). Если файл повреждён или не проходит проверку,
он переименовывается в `settings.corrupt-<время>.json`, приложение стартует со стандартными настройками и один раз
показывает предупреждение. Для тестов папку данных можно задать переменной окружения `FLOW_USER_DATA` (абсолютный путь).

## Тестовые видео

Для автотестов нужны короткие видео в `tests/fixtures/` (`cfr25.mp4`, `cfr30.webm`, `sample.webm`, `sample.mp4`, `broken.mp4`).
Они лежат в репозитории; чтобы создать заново:

```bash
node scripts/make-fixtures.mjs          # всё
node scripts/make-fixtures.mjs cfr      # только cfr25.mp4 и cfr30.webm (нужен только ffmpeg-static)
node scripts/make-fixtures.mjs chrome   # только sample.* и broken.mp4 (нужен установленный Google Chrome)
node scripts/make-fixtures.mjs players  # только players.mp4 и players.json (нужен только ffmpeg-static)
```

- `cfr25.mp4` (H.264, 25 к/с) и `cfr30.webm` (VP8, 30 к/с), по 4 секунды, 640×360: постоянная частота кадров, на каждом
  кадре крупно нарисован его номер. Делаются программой ffmpeg из пакета `ffmpeg-static` (он же вырезает клипы при экспорте). Номер рисует фильтр drawtext со шрифтом `C:/Windows/Fonts/arial.ttf` (только Windows).
- `players.mp4` + `players.json`: газон 640×360 с полосами и шумом, белая линия и три крупных «игрока» (красный, синий, жёлтый), 3 с, 25 к/с; в `players.json` координаты игроков и линии. Нужен тестам «под игроками» (ffmpeg и e2e). Делается одним ffmpeg (`drawbox` + `noise`).
- `sample.*`: 6-секундная анимация записывается через MediaRecorder в Chrome; частота кадров там переменная, что полезно
  для проверки «неидеальных» файлов. Если Chrome не умеет писать MP4, `sample.mp4` не создаётся, а тесты для него пропускаются.

Тесты на собранной программе: `FLOW_EXE=dist/win-unpacked/FlowAnalyzer.exe npx playwright test`.

## Безопасность

- `contextIsolation` включён, `nodeIntegration` выключен, `sandbox` включён.
- Интерфейс получает только функции из `window.api` (описаны в `src/shared/ipc-contract.ts`).
- Видеофайлы отдаются через собственный протокол `flow-media://`: доступны только файлы, которые пользователь сам выбрал
  (диалог или перетаскивание). Произвольные пути интерфейс запросить не может.
- Стартовый экран: интерфейс видит только сводку из файлов проектов и JPEG-эскизы (до 60 КБ) в ответе на запрос списка; проекты,
  которые можно открыть, перезаписать, переименовать или убрать, main берёт из собственной библиотеки и папки проектов (путь
  от интерфейса проверяется), «Показать в папке» работает только для таких проектов. Данные нового проекта (название, тип, дата,
  заметки, идентификатор видео) проверяются zod в main.
- Статистика: CSV собирает main из структурированных данных, проверенных zod; файл выбирает пользователь в диалоге, «Показать в папке» открывает только созданный файл.
- Экспорт: ffmpeg запускается массивом аргументов (без оболочки), видео задаётся идентификатором, папку и файл выбирает пользователь
  в диалоге main, «Открыть папку» показывает только файлы, созданные самим экспортом.
- Навигация и новые окна блокируются, разрешения (камера, микрофон и т. д.) отклоняются.
- Строгая Content-Security-Policy в `src/renderer/index.html`.
