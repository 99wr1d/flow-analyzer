# Выпуск и публикация

Порядок действий от закрытого репозитория до подписанного релиза. Шаги с пометкой **[вы]** делает владелец проекта
(аккаунты, публикация, подтверждение подписи); остальное готово в репозитории.

## 0. Что уже сделано
- История очищена от личной почты (адрес `…@users.noreply.github.com`), содержимое файлов не менялось.
- `LICENSE` (Apache-2.0), `NOTICE`, разделы «Лицензия» и «Конфиденциальность» в README.
- `.github/workflows/ci.yml` — проверки; `.github/workflows/release.yml` — сборка неподписанного установщика по тегу `v*`.
- Резервная копия старой истории: `flow-analyzer-backup-2026-11-15.bundle` рядом с проектом (не публиковать: в ней старая почта).

## 1. Новый публичный репозиторий **[вы]**
Не переключайте старый приватный репозиторий в публичный: старые коммиты с прежней почтой могут остаться доступными по хешу.
1. На GitHub включите двухфакторную защиту аккаунта (Settings → Password and authentication).
2. Старый репозиторий переименуйте (например, `flow-analyzer-old`) — так имя `flow-analyzer` освободится.
3. Создайте **новый пустой публичный** репозиторий `flow-analyzer` (без README и лицензии).
4. Отправьте в него очищенную историю (из папки проекта):
   ```bash
   git remote add public https://github.com/99wr1d/flow-analyzer.git
   git push public main
   git push public v0.20.0
   ```
   Ветки `feature/*` и `fix/*` не нужны — отправляйте только то, что хотите показать.
5. После проверки на GitHub удалите старый приватный репозиторий. Резервную копию (`.bundle`) оставьте у себя.

## 2. Проверка сборки в облаке
Откройте вкладку Actions: `CI` должен пройти на `main`. Затем создайте тег и убедитесь, что `Release build` собирает установщик:
```bash
git tag v0.21.0
git push public v0.21.0
```
Неподписанный установщик появится в артефактах запуска.

## 3. Заявка в SignPath Foundation **[вы]**
Условия: <https://signpath.org/terms>. Подавать заявку после того, как есть публичный репозиторий и хотя бы один публичный релиз.
Подготовлено: лицензия OSI, нет закрытых компонентов, нет сбора данных, сборка воспроизводима, название и версия в метаданных
совпадают с проектом (`productName: FlowAnalyzer`).
Нужно дополнительно:
- страница/раздел «Code signing policy» в README и на странице загрузки (формулировки — после одобрения, по образцу
  <https://pandoc.org/code-signing-policy.html>): ссылка на SignPath, роли команды, политика конфиденциальности;
- двухфакторная защита на SignPath и GitHub;
- уточнить у SignPath, как закрыть роли автора, рецензента и утверждающего для проекта из одного человека.

## 4. Включение подписи
После одобрения: в репозитории создайте секрет `SIGNPATH_API_TOKEN` и переменную `SIGNPATH_ORGANIZATION_ID`, раскомментируйте блок
SignPath в `release.yml`, подставьте slug проекта и политики. Каждый релиз подтверждается вручную в SignPath.

## 5. Проверка на чужом компьютере
Установите подписанный установщик на Windows 11 с включённым Smart App Control (`VerifiedAndReputablePolicyState = 1`)
и на Windows 10. Если Smart App Control пропускает — подпись достаточна. Если нет — напишите в поддержку SignPath и
проверьте цепочку доверия сертификата.

## Mac (отдельно)
SignPath Foundation подписывает только Windows. Для Mac нужны Apple Developer ID (99 долларов в год) и нотаризация;
пока — сборка без подписи с обходом «Конфиденциальность и безопасность → Всё равно открыть». Заменить `build/icon.icns`
(сейчас шаблонный значок) и собирать на `macos-latest`.
